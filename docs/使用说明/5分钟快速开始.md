# 5 分钟快速开始

Strixnova当前面向“我能说明想要的效果，但不想先学完整软件工程”的本地项目负责人。你不需要选择方法论或测试框架。

首次使用先按[安装与首次使用](installation-and-first-use.md)准备 Strixnova：机器已有 Windows x64、Python 3.12 和 Git 后，解压对应离线包并运行安装入口。包里提供 Strixnova 和 Python 依赖库，不包含操作系统、Python 或 Git 的安装程序。让 Agent 读取安装返回的精确入口和配套 Skill，随后再进入下面的工程流程。

## 1. 说清效果

把愿望直接告诉能够执行命令的 Coding Agent（智能编码代理），例如：

> 日常测试等待太久，请在不删除必要覆盖的前提下分析并优化。

智能编码代理会自行调查可查事实，只追问真正影响方向的内容，例如哪些体验最重要、什么不能破坏、怎样才算成功。没有必要把一次讨论拆成大量表格。

## 2. 确认方向

你会看到一份通俗方向摘要：目标、范围、非目标、关键取舍和验收方向。内容正确时确认；不正确就直接指出，Strixnova 不会把未确认草稿当实施授权。

可确认摘要还会明确约束。范围和验收方向至少各有一项；其他项目即使确实没有，也会明确为空，而不是悄悄漏掉。尚有关键问题时，界面会显示具体 blocker 并继续讨论。

## 3. 确认完整工程方案

Coding Agent（智能编码代理）自主调查项目，引用已确认方向、精确长期权威和直接证据，形成一份按真实影响裁剪的工程评估，再自检事实依据、项目针对性、范围和遗漏。十二个影响维度仍完整分类，但不受影响项只列名称；没有真实内容的风险、设计、操作或验证章节可以省略。Strixnova程序只校验结构、真实引用、关系和已声明规则，不要求同一智能编码代理把整份内容重新装入上下文做形式复审。

你看到的是一份完整但按实际影响裁剪的方案：要改什么、为何这样改、风险、验证和限制。小而可逆的改动不会因为文件多就套上最重流程；很小但涉及安全或数据的改动也不会被低估。

## 4. 等待实施和验证

确认方案后，Strixnova才建立本地 Git（版本管理系统）分支。单项建设使用当前主工作树；需要并行时才为新增事项建立仓库外 worktree（工作树）。智能编码代理自主实施，并只运行方案明确选择的本地检查。没有执行的验证必须显示为“未运行”和原因。

如果事项本身没有仓库交付，方案可以选择最低 A0 保障。这不是额外工作模式，Agent 平时调查代码也不需要创建 WorkItem。真正进入 Strixnova 的 A0 不会建立空分支或提交，只做紧凑的完整影响分类并展示实际发现。没有适用检查时会显示 `not_required`，不会生成假回执。

## 5. 确认实际结果

你会看到：

- 实际实现了什么；
- 每项验证真实是通过、失败、阻断还是未运行；
- 与方案有什么偏差；
- 仍有哪些限制；
- 是否形成或更新长期 ADR、接口或项目政策文件。

只有你确认实际结果后，智能编码代理才形成原子提交。Strixnova随后本地合入目标分支并安全清理自己创建的工作区。是否推送到远程由你另行管理。

## 怎样由智能编码代理调用

安装 Strixnova后，能够加载当前安装包随附唯一 Strixnova Skill（技能）、执行命令并理解结构化输出的受支持智能编码代理可以使用公开命令。若宿主尚未直接加载随包 Skill，先用 `strixnova setup-agent`（安装代理说明）复制它；该命令不修改智能编码代理配置，也不安装 hook（钩子）或插件。Skill 只在用户明确要求使用 Strixnova 时触发，不是授权或语义权威。

智能编码代理每次只读取 CurrentAction（当前动作）和当前动作需要的一项记录。当前动作只是“现在该提交哪类事实”的小指针，不限制智能编码代理如何阅读代码、选择工具或使用子代理。本期没有 WebUI（网页界面）入口，用户无需依赖界面完成流程。

如果看到 Authority 格式错误，先停止写入，核对实际程序与数据支持范围并保留原文件。当前精确格式以 `strixnova upgrade runtime` 为准，不支持的格式没有自动转换路径；不要删除 Git 历史、ADR、工程材料或业务数据绕过拒绝。
