# 审阅上下文只读查询

本查询为审阅 Agent 准备资料，不执行审阅、生成修复或创建 WorkItem。它支持本次改动，也支持没有新改动时的指定模块。资料由同一次只读结果输出为 JSON 或 Markdown，不成为第二份项目规则。

## 读取合同并选择范围

```powershell
strixnova context contract review
```

下面是已配置单仓库项目的改动查询。仓库身份应复制项目配置中的真实身份，不能把示例值当作当前项目身份。

```json
{
  "schema_version": "strixnova.review-context-request.v1",
  "mode": "changes",
  "basis_ref": "main",
  "repositories": [
    {"repository_id": "REPO-1111111111111111", "base_ref": "main", "ref": null}
  ]
}
```

`basis_ref` 选择配置仓库中作为规则依据的提交；省略时使用配置中的 `default_integration_ref`。若两者都没有，返回缺口而不猜测规则版本。各仓库的 `ref` 必须显式提供，`null` 表示当前工作树最终内容；提交或本地引用则解析为不可变提交。工作树范围包含相对基点的已暂存与未暂存合并结果，以及未被 Git 忽略的新文件；不单独提供“只审暂存区”的内容版本。

```powershell
strixnova context review --project-dir . --input '@review-request.json'
strixnova context review --project-dir . --input '@review-request.json' --format markdown
```

模块查询把 `mode` 改为 `modules`，增加真实 `module_ids`，删除各仓库的 `base_ref`。它按所选依据中的模块身份取得已登记实现，不要求存在 diff；同时列出所选仓库受管范围内尚未登记的候选文件，保留归属缺口，由 Agent 判断其相关性。

```json
{
  "schema_version": "strixnova.review-context-request.v1",
  "mode": "modules",
  "basis_ref": "main",
  "module_ids": ["MODULE-1111111111111111"],
  "repositories": [{"repository_id": "REPO-1111111111111111", "ref": null}]
}
```

实际调用直接复制真实仓库和模块身份。查询不会按模块名称或目录名猜测身份。改动查询也可以提供 `module_ids`，作为 Agent 已明确选择的额外调查起点。

分离项目入口或多仓库场景沿用现有 `--project-bindings` 全局参数，例如 `strixnova --project-bindings bindings.json context review --input @review-request.json`；也可在请求中传入同一 `bindings` 对象。两个来源同时提供时必须相同。只指定本次需读的仓库及其内容版本；关联的其他仓库未选版本时保留缺口，不偷偷使用最新分支。缺少配置时只报告无法确定身份，不初始化项目。

## 怎样使用返回资料

- `product_guardrails` 保留所读产品的全部能力、非目标和约束，程序不决定它们的语义适用性。
- `architecture` 包含选中模块、触及关系的端点与中介定义、默认关系政策、适用模块约束及全部全局架构约束。
- `domain_facts` 按显式事实引用展开，保留精确来源引用。
- `engineering_policy.rules` 保留所选依据版本的完整规则解释、证据要求和裁剪结果；`rule_sources`、`project_sources` 提供原始来源。完整清单不表示每条规则都在语义上适用于本次修改，适用性由审阅者判断。
- `implementation` 是规则依据版本中已经登记的归属、依赖、责任和偏离，不是一次新运行的依赖分析。
- `files` 和 `content_snapshots` 绑定待审代码的真实字节、仓库与版本；`recorded_observation_current=false` 表示它与登记观察不同。删除或重命名保留原路径，旧代码可按 `changes.base_commit` 继续读取。
- `sources` 给出规则来源、实际提交及声明状态；候选或非当前材料同时进入缺口，不可当作已确认规则。
- 显式提供 `work_item_id` 时，可同时取得原事项版本中的方向、方案与回执。它们是历史记录，查询不会重新验证命令或接受结果。

`status=available` 只表示当前资料查询没有报告缺口；`partial` 表示已返回可靠部分，但有缺失、过期或未展开项。两者都不表示代码已经审阅通过。缺失权威、未知模块、未归属文件和未选版本的关联仓库保持可见；身份或精确版本矛盾会拒绝结果。

## 预算与继续读取

默认最多展开 100 个文件，内联原内容总预算 65,536 字节、每文件窗口最多 16,384 字节，JSON 结果预算 262,144 字节。可用请求字段 `max_files`、`max_content_bytes` 和 `max_output_bytes` 在合同上限内调整。

超出文件预算的路径放入 `omitted_files`。内容窗口给出 `next_offset` 和完整内容摘要；Base64 是原字节，窗口可能截在 UTF-8 字符中间，应拼接字节后解码。内容预算或输出预算不足时保留引用与缺口；必要来源和规则本身无法容纳时拒绝该预算，不静默删去产品护栏。

Agent 根据精确引用继续读文件、追查调用方并判断语义。查询只提供已登记关系能解释的起点，不证明动态调用、跨文件业务影响或全部测试覆盖已经查全。范围内工作树内容或变化清单在读取期间改变时，重新查询。

本能力属于源码增量；应使用包含此功能的程序。本说明不证明用户默认安装或当前宿主已加载该版本，也不要求安装 OCR。
