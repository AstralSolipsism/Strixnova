# 当前行动材料有界读取

`strixnova next --work-item-id <ID>` 返回当前行动。通过其公开引用读取材料，
不会推进事项、采用权威或建立新的业务状态。默认完整响应预算为 4096 字节，
包含 JSON 外壳、ASCII 转义和换行；程序内部读取接口仍可明确选择原始值或有界视图。

```powershell
strixnova next --work-item-id <ID> --record engineering.plan
strixnova next --work-item-id <ID> --record 'engineering.plan#/actual_result_requirements'
strixnova next --work-item-id <ID> --record 'input.contract:present_actual_result#/payload_schema'
```

只有当前动作已开放的父记录及其子项可以读取，不开放任意内部状态。普通对象字段也可沿用
`engineering.plan.actual_result_requirements`；返回的规范引用使用 JSON Pointer：`~1` 表示
字段名中的 `/`，`~0` 表示 `~`。复制返回的引用，不自行拼接复杂路径。不存在的路径报错，
已存在且值为 null 的字段仍返回 null。

## 如何解释结果

- `records`：本次完整返回的值。
- `record_pages`：较大值的目录、列表页或文字片段。对象与数组的 `entries` 包含 `ref`、类型，
  以及能容纳的完整 `value`；`value_omitted=true` 和 `unexpanded_refs` 表示仍需读取正文。
- `next_cursor`：同一个记录还有后续条目或文字；复制到 `--cursor`，一次续读一个记录。
- `reading.unread_refs`：批量请求中当前预算没有容纳的记录，另行请求。
- `record_sources`：公开根引用与源内容 SHA-256；`reading.complete` 只说明这次响应是否包含
  所有请求的完整值，不证明 Agent 已理解或审阅过材料。目录翻到末尾也不等于子项正文全已取得。

```powershell
strixnova next --work-item-id <ID> --record '<原引用>' --cursor '<返回的游标>'
strixnova next --work-item-id <ID> --record '<返回的子引用>' --expected-version <V> --expected-sha256 <源摘要>
```

游标绑定事项身份、版本、根内容和选定路径；来源变化返回 `record_read_source_changed`，
不能把不同版本的页拼在一起。子项跨次读取时显式携带原版本和源摘要。该读取不持久化新的
快照状态；每次从既有来源重建并核对身份。

文字页通过 `text` 返回完整 Unicode 码点片段，`start` 与 `total_count` 的单位为码点；
沿游标顺序拼接，不把它当 UTF-8 字节偏移。每页外壳仍是完整 JSON。超长单个字段也可继续读，
不需要读取私有数据库或使用 Shell 管道。

`--max-output-bytes` 可在 512–1048576 之间设置，按宿主容量选择；元数据或单个引用本身无法
容纳时明确报告预算不足。多项材料共享同一个总预算。不要把正文摘要当作正式约束原文，
也不要把未返回项当成不存在。

## 开始、恢复和纠偏时取得实施材料

当前行动列出 `engineering.execution_context` 时，通过同一 `next --record` 读取：

```powershell
strixnova next --work-item-id <ID> --record 'engineering.execution_context'
```

材料包含原始方向及约束、当前切片及文件操作、已确认方案中的核验安排、与方案精确绑定的
评估材料、尚未闭合的发现，以及按文件归属和显式关系展开的项目规则。它不是新的权威或
状态。原有切片记录也在 `execution_context` 字段提供同一材料，按当前需要选择一个入口。

按返回的子引用继续取得所需正文。例如当前记录可用时，可直接读取
`engineering.execution_context#/direction/constraints`。续读仍绑定 `--expected-version`
和 `--expected-sha256`；方案或关联规则内容变化后，旧摘要不能继续用于新材料。

`gaps` 标明无法与当前方案绑定的评估；`project_rules.gaps` 标明缺少规则依据、未知归属或
尚未采用的材料。没有归属的新增文件仍取得完整产品护栏和工程政策，并明确需要 Agent
调查其相关模块。程序不按关键词猜测适用性，也不把提供原文等同于审阅通过。

`project_rules.engineering_policy.rules` 提供同一来源版本的基础规则、项目扩展及裁剪后的规则原文，
包含解释和证据要求；`rule_sources` 提供规则来源，`project_sources` 保留项目规范文件入口。
这是完整政策清单，不是程序对语义适用性的判断；当前方案的 `applicable_rules` 仍保留其原有声明。
正文超出单次预算时，沿返回引用继续读取，不能把只有编号的条目当作已读完规则。

项目规则的 `basis_kind` 为 `integrated_authorities` 时来自明确集成/调查提交；为
`confirmed_execution_candidate` 时来自本次方案已记录确认的工作区候选，程序已核对相关
上游决定、修订与当前文件内容。确认后改写不能沿用旧决定。未完成确认的候选不替换集成规则，
可从 `authority_changes` 看到哪些计划权威变化尚无匹配决定。未闭合发现同时承接方案审阅和
同一方案的最终权威审阅，其他方案的审阅不拼入。

## 实际结果与审阅时的内容绑定

复核实际实现之前，通过当前行动提供的记录取得审阅对象：

```powershell
strixnova next --work-item-id <ID> --record 'engineering.review_subject'
```

它包含当前方案、方向、已记录证据、声明仓库输入及已采用规则依据的身份和内容快照。
实际结果使用当前 `strixnova.actual-result.v1` 合同，将这次读取返回的 `subject_ref` 填入
`review_subject_ref`。无需让 Agent 重写原文或文件清单。旧 v4 历史记录仍按原有含义读取。

程序接收结果时重新计算同一范围的身份，变化时返回 `review_subject_changed`，不推进结果
状态。应重新取得当前对象并复核受影响的实现与证据；不能只换一串身份继续提交原结论。
身份一致不能证明 Agent 真正读过材料、声明范围已穷尽或判断正确，这些仍需相应语义审阅。

## 覆盖边界

预算适用于指定事项的 `next` 读取，涵盖方案、回执和输入合同，不宣称所有 CLI 命令都已
采用同一输出预算。写命令原回执输出被宿主截断时，重新查询 `next`，或通过独立的 `history`
读取过去回执；不要重复执行写操作。未指定事项的事项列表仍沿用既有接口。

用法和 Skill 已同步。实际测试、安装与真实宿主验证结果分别记录，不从文档推定验收通过。
