# 本地验证与临时产物管理

本入口管理 Strixnova 开发期间的测试和前台命令验收目录。它复用现有进程监督工具，不调用 Strixnova CLI 管理本项目，也不创建本项目 WorkItem。

## 测试

所有命令使用仓库根 Python 3.12 环境：

```powershell
# 日常只跑受影响测试；其余 pytest 参数放在 -- 后。
.venv\Scripts\python.exe scripts\local_validation.py test -- tests\unit\test_local_validation.py

# 最终快速、全量候选保留证据，但仍自动回收工作文件。
.venv\Scripts\python.exe scripts\local_validation.py test --pin
.venv\Scripts\python.exe scripts\local_validation.py test --full --pin
```

底层仍运行既有 pytest 套件，默认 8 个 worker、loadgroup 分发；快速模式排除 slow。临时目录、JUnit 和 pytest 缓存由入口指定，不接受另行覆盖这些输出位置。失败摘要、原始标准输出/错误及 JUnit 保留在运行目录，返回状态区分测试结果与清理失败。

## 功能回归与仓库状态检查

默认测试入口只收集 `tests/unit` 和 `tests/integration`。功能回归使用隔离样例验证程序行为：例如样例源码改变后，正确报告旧证据失效应当让测试通过。

`tests/repository_checks` 单独核对当前 Strixnova 仓库的源码、对齐快照、实际依赖及长期材料是否一致。它不混入默认快速或全量功能套件，需要时显式选择：

```powershell
.venv\Scripts\python.exe scripts\local_validation.py test -- tests\repository_checks
```

这组检查的失败是当前仓库状态问题，不能直接当成功能回归失败；但原有约束和失败信号继续保留。更新快照需要复核实际变化，不能只替换散列让结果变绿。

## 目录和生命周期

每轮位于 `.artifacts/validation/<运行ID>/`：

| 内容 | 用途与保留 |
| --- | --- |
| work/ | 测试项目、数据库、临时环境和缓存；成功后回收 |
| evidence/ | JUnit 和调用方显式保存的关键证据 |
| result.json、stdout.log、stderr.log | 一份运行记录及原始输出；普通成功保留最近 3 轮，失败保留 7 天 |
| .lock | 运行期间的排他文件锁；清理跳过仍持锁的运行 |

新运行开始和结束时都会检查过期记录。`--pin` 保留证据，成功的工作区仍清理；`--keep-workspace` 保留工作区及证据，直到操作者显式释放。未收口或进程退出状态无法确认的运行继续保留，不能只凭时间到期删掉。

```powershell
# 只清理满足保留规则、已经结束且有匹配归属的运行。
.venv\Scripts\python.exe scripts\local_validation.py clean

# 精确释放已结束的一轮；也会删除它的证据，需先完成必要保全。
.venv\Scripts\python.exe scripts\local_validation.py clean --release 012345abcdef

# 仅释放一个已结束运行的 work/，保留并固定其证据、日志和结果记录。
.venv\Scripts\python.exe scripts\local_validation.py clean --release-workspace 012345abcdef
```

不认识的目录、归属不匹配的记录、链接和清理错误会明确报告。删除边界固定在本入口拥有的验证目录内；历史归档、根 `.venv`、源码、Git 元数据及真实项目状态不属于自动清理范围。

`--release-workspace` 与 `--release` 互斥，只处理指定的一轮。前者会设置证据保留标记，后续普通
清理也不会轮换掉这些记录；确认不再需要时才使用完整释放。保存在 `work/` 内的唯一证据、wheel
或仍需使用的候选环境必须先另行保全；该入口不推断哪些工作文件有长期价值，也不自动归档。

## 其他验收命令

```powershell
.venv\Scripts\python.exe scripts\local_validation.py run --label build --pin -- .venv\Scripts\python.exe scripts\build_clean_wheel.py --output-dir .artifacts/candidates/local-build
```

调用脚本通过环境变量 `STRIXNOVA_VALIDATION_WORK` 使用临时工作区，通过 `STRIXNOVA_VALIDATION_EVIDENCE` 保存需要留下的证据。该入口适用于明确的前台、一次性命令；异步 Agent 的工作区应显式保留，等 Agent 和相关进程结束后再收口释放。

wheel 继续只能用 `scripts/build_clean_wheel.py` 构建。被最终验收回执引用的 wheel 保留一份在 `.artifacts/candidates/` 等正式位置；不要把唯一副本留在成功后会删除的 work/ 中。已正式保存的验收证据也不按临时目录规则清理。

本机已将当前验收 wheel 保全到 `.artifacts/candidates/history-upgrade/<wheel摘要>/`，并将一套离线依赖集中到 `.artifacts/wheelhouse/win-py312/`。缓存是否满足安装要求仍以对应依赖锁和摘要为准。

临时项目和可重建缓存完成后直接回收，只归档不可替代的输入、关键失败证据和最终验证记录，避免把完整工作区再打包成新的长期负担。

首次离线分发只组装已经构建的 clean wheel，不再构建一遍。维护者使用 `scripts/build_offline_bundle.py --wheel <wheel> --wheelhouse <匹配依赖目录> --output-dir <新目录>`，它按目标锁核对 Windows x64 / Python 3.12 依赖并生成 ZIP 与清单。Windows、Python、Git 安装程序不属于分发内容。

技术安装检查使用 `local_validation.py run --label offline-installation --pin -- .venv\Scripts\python.exe scripts\check_offline_installation.py --bundle <解压目录>`。检查入口只在受管临时目录内安装一次、核对实际命令与文件并验证同组合重复运行；成功后临时环境自动回收，回执单独保留。它不运行 Agent 效果场景，不代表宿主已加载 Skill。
