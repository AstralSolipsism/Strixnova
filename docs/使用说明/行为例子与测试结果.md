# 行为例子与测试结果

Strixnova 把 BDD / ATDD 中“先共同理解行为，再用实际证据验证”的做法放进现有方向、工程方案和实际结果。你不需要学习 Gherkin、填写测试字段或再通过一个 BDD 确认关口。

## 一个完整例子

你提出：“库存不够时，要拒绝预留，而且不能偷偷扣掉库存。”

Agent 先调查现有规则，再把预期讲成你能判断的例子：

| 前提 | 操作 | 期望 |
| --- | --- | --- |
| 库存只有 2 件 | 预留 3 件 | 拒绝请求，库存仍为 2 件 |

这不是把已经跑过的测试换成中文。期望先来自你的需求；如果“可以部分预留”还是“必须整单拒绝”尚未决定，Agent 会先解释影响并与你讨论。已经明确的事情不需要重复询问。

这个例子保存在方向的验收条件里，随原有方向一起确认。Agent 再安排具体测试或其他核验方式，随原有工程方案确认。程序会检查每个例子是否都有安排，不能只说“大套件覆盖了需求”。

实施时，Agent 编写测试并检查断言：测试不仅要看返回了错误，还要检查库存没有减少。最终由 Strixnova 执行方案中的命令，报告实际运行了哪些原生测试。结果仍在原有实际结果确认点展示。

## 结果怎样看

| 实际情况 | 应怎样解释 |
| --- | --- |
| 用例实际通过，Agent 也确认断言覆盖期望 | 该例子有本次执行证据和断言审阅；仍不等于程序证明业务含义一定正确 |
| 命令整体通过，但该用例被跳过 | 这个例子尚未实际验证，结果必须保留缺口 |
| 测试名称没有收集到、参数组漏跑 | 不能按相似名字或其他测试通过补算 |
| 测试通过，但没有检查库存副作用 | 执行事实通过，断言审阅不足；应补测试或明确限制 |
| 环境无法运行，或有充分理由只做审阅 | 说明实际核验方式与限制，不显示为自动测试通过 |

一个验收条件包含多个例子时，父项从各个例子的结果汇总，不能用一个成功例子遮住其他遗漏。程序检查结构、引用和执行事实；预期是否合理、例子是否充分、断言是否真正检查了承诺，由 Agent 作有依据的判断。

## 哪些工作需要例子

用户或外部调用方可观察的行为变化默认需要，例如错误处理、权限、边界条件、状态转换和接口效果。不是每项工作都需要扩展成业务场景：纯说明文字或保持行为的机械修改，可以写明“不适用”的具体理由。

有行为例子不等于每个例子都必须自动化。当前可选自动测试、Agent 审阅、已有证据复用或明确未核验。采用其他方式时必须解释依据和后果，不能靠没有测试命令让义务消失。

## 测试后又改了代码

带原生报告的验证会记录 Agent 声明的受测源码、测试、夹具和配置文件的实际字节，包括尚未提交的代码。之后这些输入改变，就要求重测；原来的运行记录仍然保留，不被覆盖。

这份检查只涵盖声明的文件，不自动发现所有依赖。Agent 仍要检查遗漏依赖、环境变化和范围之外的影响。若变化改变了期望行为，回到方向修订；只是修正实现，则按当前方向重新验证，无需为同一个业务决定再加确认。

## 产物放在哪里

每条带报告的验证命令增加一份：

~~~
<项目>/.strixnova/artifacts/<事项ID>/<回执ID>.cases.json
~~~

它和原有 stdout、stderr 日志放在同一位置，一份可以记录多个例子及测试用例。方案中的测试关联、断言审阅和结果沿用事项原有数据库，不建立第二套 BDD 数据库或目录。

历史查询通过返回的 output:<回执ID>:cases 引用读取报告，支持分页和内容完整性核验。原文件丢失与被改动分别报告；它们不会改写“当时执行了什么”的原记录。升级备份沿用既有证据目录保护。

## 当前适配范围

原生用例报告首批支持 pytest / pytest-xdist；本轮测试环境为 Python 3.12、pytest 9.1.1、pytest-xdist 3.8.0。目标项目必须已有相应测试环境，Strixnova 不替它安装框架。其他框架目前可以明确安排其他核验方式，接入原生执行报告还需开发对应适配器。

已记录的例子、计划和执行事实各自绑定当时的具体版本与内容。后续方向或方案变化必须按现有确认与验证流程处理，不能补造先前未执行的测试或通过记录。
