# 项目上下文只读查询

审阅资料准备使用新增的 `context review` 只读操作，见[审阅上下文只读查询](审阅上下文只读查询.md)。下面保留候选声明探查与原字节读取的合同说明。

本源码增量提供 context 查询，用于检查明确提交的候选项目声明、本机仓库绑定和仓库内容。它不采用声明，不修改 strixnova-project.yaml，不创建 WorkItem、数据库、分支或维护记录；普通多仓库事项写流程尚未接管。

2026-09-15 已接通版本化配置及跨仓库权威读取，见[项目配置与跨仓库权威读取](项目配置与跨仓库权威读取.md)。本文继续说明直接提交候选声明的只读探查合同。

应使用包含此增量的 Strixnova 程序。本文描述公开源码合同，不证明当前宿主已经安装或加载对应构建，也不表示完整多仓库流程可用。

## 1. 先读取输入合同

```powershell
strixnova context contract inspect
strixnova context contract read
```

合同读取不要求项目目录。inspect 和 read 都使用现有 --input 传输方式，接受 JSON、@文件或 @- 的 UTF-8 标准输入。

## 2. 检查候选声明与本机绑定

假设项目入口、frontend 和 backend 是同一父目录下的三个目录，项目入口本身不是 Git 仓库。以下身份仅用于示例，实际身份应来自明确的项目声明。

把以下内容保存为 context-request.json：

```json
{
  "schema_version": "strixnova.project-context-inspect.v1",
  "declaration": {
    "project_id": "PROJECT-1111111111111111",
    "repositories": [
      {
        "repository_id": "REPO-1111111111111111",
        "owner_project_id": "PROJECT-1111111111111111",
        "purpose": "前端"
      },
      {
        "repository_id": "REPO-2222222222222222",
        "owner_project_id": "PROJECT-1111111111111111",
        "purpose": "后端"
      }
    ]
  },
  "bindings": {
    "project_id": "PROJECT-1111111111111111",
    "management_root": ".",
    "repositories": [
      {"repository_id": "REPO-1111111111111111", "path": "../frontend"},
      {"repository_id": "REPO-2222222222222222", "path": "../backend"}
    ]
  }
}
```

```powershell
strixnova context inspect --project-dir . --input '@context-request.json'
```

项目入口通过 --project-dir 明确选择。本机相对路径相对于该入口解析，绝对路径也可明确提供；management_root 只表示候选管理位置，不会因此创建目录或数据库。

每个仓库会分别返回 available、not_bound、missing、invalid 或 conflict。未绑定、缺失或无效的无关仓库不阻止读取另一个可用仓库。一个 Git 共同目录被绑定为两个仓库身份时，两项均标为 conflict；同仓库链接工作树可以作为唯一明确绑定。

成员仓库的 owner_project_id 必须与项目相同。其他项目负责的仓库放在 declaration.external_repositories 中，结构与成员记录相同，但 owner_project_id 必须不同；它们只作为外部依赖范围，不能由本项目取得修改归属。本机绑定只定位已经声明的身份，不能隐式新增仓库。

declaration_sha256 绑定规范化声明内容，bindings_sha256 绑定解析后的入口、管理位置、仓库路径和可用性。它们不是用户确认指纹，也不证明声明已被采用或全机仓库身份已经核验。

## 3. 读取明确仓库的内容窗口

保留声明和绑定，把 schema_version 改为 strixnova.project-context-read.v1，并增加以下字段：

```json
{
  "reference": {
    "repository_id": "REPO-1111111111111111",
    "path": "src/api.ts",
    "ref": "HEAD"
  },
  "offset": 0,
  "limit": 4096
}
```

上面的片段表示需要增加的字段，完整请求仍须包含 schema_version、declaration 和 bindings。保存完整请求后执行：

```powershell
strixnova context read --project-dir . --input '@read-request.json'
```

ref 指向明确的本地 Git 提交或可解析为提交的引用，返回 observed_commit 是实际解析后的不可变提交。省略 ref 或设为 null 时读取当前工作树，并明确返回 working_tree 范围，不冒充已采用版本。

内容路径必须是所选仓库内的普通相对路径，使用 /；绝对路径、上级穿越、.git 和 .strixnova 都不能作为内容路径。绑定允许分离仓库的位置，不会放宽仓库内部的读取范围。符号链接和联接点不能用来隐藏本机绑定的实际位置。

工作树内容不能通过外层仓库身份跨入嵌套仓库或另一个工作树。嵌套仓库应使用自己的明确绑定读取；不可变提交则按该提交的真实 Git 内容读取，不用当前工作树布局重判历史内容。

返回 content_base64 是窗口内的原字节，sha256 对应完整 Git 规范内容字节，size_bytes 是完整长度。offset 和 limit 按字节计数，因此窗口可以截在 UTF-8 字符中间；应先解码 Base64 并拼接字节，再解释文本。

默认窗口为 65,536 字节，单次最多 1,048,576 字节。存在后续内容时，next_offset 给出下一位置。后续请求可同时提交上次的 expected_sha256；内容变化会返回 repository_content_changed，不会无提示地拼接不同内容。读取提交内容时，也可直接沿用返回的 observed_commit。

窗口只限制返回长度；当前实现仍完整读取文件以计算摘要。提交文件沿用底层 16 MiB 输出预算，单对象另预留 160 字节批处理头部，超过该范围会拒绝；工作树读取也不是流式处理。本轮没有扩大既有大文件读取能力。

## 4. 结果边界

- declaration_adopted 始终为 false：这是明确候选输入的只读查询，没有项目采用动作。
- writes_performed 为 false：没有项目状态或 Git 内容写入。
- 仓库的声明身份、本机 Git 根和共同目录分别保留；本地核对不提供全局唯一性或宿主权限认证。
- 输入格式错误、身份重复、归属矛盾和未知绑定会直接拒绝；单仓库不可用原因保存在其 issue_code，实际读取该仓库时返回同一原因。
- 本入口只读。验证、采用和多仓库事项写入分别使用对应公开合同，不能把一次读取成功解释为它们已经完成。

多仓库使用见[整体方案与交付](多仓库事项与整体方案.md)，当前候选的验证边界见[验证状态](../engineering/validation-status.md)。
