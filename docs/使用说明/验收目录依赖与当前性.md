# 验收目录的依赖与当前性

`scripts/check_guided_formation_acceptance.py` 只核对已登记依赖与证据定位，不启动 Agent、不生成语义结论、不自动改写验收登记。

```powershell
.venv\Scripts\python.exe scripts\check_guided_formation_acceptance.py
.venv\Scripts\python.exe scripts\check_guided_formation_acceptance.py --require-current
```

输出为 `strixnova.guided-formation-acceptance-check.v1`。`skill_current_count` 只统计 Skill 依赖仍匹配的场景；`current_evidence_count` 要求各已声明维度均可核对。`unassessed_evidence_count` 表示缺少完整依赖记录，不能读成失败或未曾验收。`--require-current` 对待验、失效和未评估均返回非零。

## 新记录

当前 v1 目录对每个场景明确登记 `execution_dependencies`：

- `runtime`：这次行为实际依赖的运行实现或制品；
- `harness`：实际使用的驱动、检查及判定脚本；
- `fixture`：固定输入、配置和必要夹具；
- `evidence`：原始回执和该场景报告，必须包括 `evidence.path` 指向的文件。

每组字段为 `status`、`reason`、`files`。状态为 `recorded` 时必须登记非空的 `{path, sha256}` 列表，路径为仓库内规范相对路径，摘要按原始文件字节计算；缺失文件与内容变化均标记 `stale`。重复路径、越界路径或非法摘要拒绝。

确实不适用的执行维度由记录者以 `not_applicable` 和理由声明，文件列表为空；程序不判断理由是否正确。证据组不能声明不适用。缺少原始绑定时使用 `unrecorded`；全部尚未登记可以使用 `execution_dependencies: null`。未执行的 `pending` 场景只能使用 null，不能从当前文件补造过去的执行绑定。

范围由真实执行和审阅安排明确选择，不根据关键词猜测依赖；`freshness_scope=declared_dependencies_only` 不证明声明范围已穷尽。相同制品版本号也不能代替内容身份。

## 执行与证据边界

本项目初始目录中的 50 项当前要求从待验状态开始。只有真实执行、原始回执与独立审阅支持时，才登记相应结论和精确依赖；不能从当前文件内容补造过去的执行绑定。

依赖变化不自动等于功能失败，不自动扩大成全量重验，更不能只换指纹恢复通过。固定隔离对话、执行者、模型、权限和投递条件见[隔离 Agent 验收方案](../engineering/agent-acceptance.md)，实际进度见[当前验证状态](../engineering/validation-status.md)。
