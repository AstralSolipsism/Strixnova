# 开发环境根本法

> 本文件只约束 Strixnova 仓库自身开发，不进入通用 WorkItem 产品领域。

## Python

唯一有效解释器是仓库根 `.venv\Scripts\python.exe`，Python 3.12，由 uv 管理并以 editable 方式安装当前 Strixnova。

禁止裸调用 `python` 或 `python3`，禁止向系统 Python 安装 Strixnova 或开发依赖。系统解释器产生的测试结果不作为本仓库证据。

最终 wheel 安装验收需要证明普通安装不偷用 editable 源码，因此允许由仓库根 venv 创建一次性隔离 venv，并只用其解释器安装锁定运行依赖、wheel、执行 `pip check`、导入和 CLI 检查。该环境不是源码测试解释器，不能替代根 venv 的测试证据，验收后可删除。

本仓库当前不使用 CI；测试、构建和隔离安装验收均在本地执行，不新增或恢复 GitHub Actions 工作流。重新启用 CI 需要项目负责人明确决定。

本地测试与构建工具由仓库根 `requirements-dev-win-py312.in` / `requirements-dev-win-py312.txt` 锁定，运行依赖仍由 `strixnova/requirements-lock-win-py312.txt` 锁定；只在仓库 venv 内按需要安装。

wheel 只允许通过 `.venv\Scripts\python.exe scripts\build_clean_wheel.py` 构建。该入口仅复制 `strixnova/pyproject.toml`、`strixnova/README.md` 和 `strixnova/src` 到系统临时目录，排除所有生成目录和缓存，并要求 wheel 内随包资源与当前源码逐路径、逐字节一致后才输出成品。直接在仓库源目录运行 `python -m build` 不能作为交付证据。

需要依赖时只更新项目声明与锁文件，并安装到项目 venv。

## 测试

开发时先运行受影响的 Module 行为测试；跨越 Authority、GitWorkspace、VerificationRunner 或 Host 时再运行对应集成测试。最终才运行：

```powershell
.venv\Scripts\python.exe -m pytest tests\unit tests\integration -m "not slow" -n 8 -q --dist=loadgroup
.venv\Scripts\python.exe -m pytest tests\unit tests\integration -n 8 -q --dist=loadgroup
```

最终候选的快速套件和全量套件各测一次；只有失败、明显环境抖动或结果无法解释时才复测。记录总耗时、用例数、最慢项和外部进程数；不设置人为秒数门槛，也不为时间数字删除独立行为覆盖。

真实 Git 测试会启动大量短进程。pytest 通过进程级 Git 配置关闭临时仓库的 fsmonitor，避免系统级 fsmonitor 为每个短命仓库留下常驻 daemon；该修复后 `-n 8 --dist=loadgroup` 已完成快速和全量实测，因此作为当前默认值。这个覆盖不修改用户 Git 配置或 Strixnova 产品行为。

## WebUI 边界

本期不构建或交付 WebUI，也不把 Node 纳入开发与验收环境。旧 WebUI 不作为产品入口或可用性证据；核心功能稳定后再按新的产品设计整体重构。

## Git 与本轮开发

Strixnova 不管理自身建设事项，不调用自身 CLI、Skill、插件或 hooks。本轮按用户批准的工程方案使用普通 Git 原子提交；每个批次先做受影响验证，全部批次完成后再做快速、全量和安装包验收。

不得修改或删除用户未跟踪目录与 Git 历史。已经退役的 `strixnova-changes/**` 不进入当前源码树，不得重新跟踪或提交；本地残留只由 `.gitignore` 隔离。不得执行远程 Git 操作，除非项目负责人另行明确要求。
