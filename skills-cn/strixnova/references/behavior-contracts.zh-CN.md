# 将高风险交互或接口明确到可以实施

> 本文件是正式 Skill 的中文审阅映射，不是另一个可运行 Skill。

只有真实 API、数据、权限、并发、兼容或恢复风险需要比普通方向/方案更细的说明时，才读
本规程并选择适用部分。简单局部计算或措辞修改不需要新的合同文档或遍历全部风险类别。

从真实调用方、当前接口和所属需求开始，复用项目的 Schema、API 说明、测试和术语。
缺失决定进入既有方案或审阅。技术细节应当
能改变实施、验证或负责人必须作出的决定。

## 描述可观察操作

明确行动者、输入、前置条件、结果和持久影响。在现有接口确实区分的地方，说明无效输入、
资源缺失、权限拒绝、业务拒绝、冲突及依赖不可用。每种结果产生或保留哪些效果，必须清楚。
沿用已规定的错误优先顺序及信息披露规则，不悄悄新选一套；HTTP 状态或异常类型不构成完整行为。

读取操作按需说明过滤、顺序、分页和快照/新鲜度。写入操作明确资源或操作身份，以及何时
能够知道成功。调用方超时后可能不知道操作是否已提交；核对办法应来自真实受支持的接口。

## 明确会改变结果的边界

| 适用风险 | 需要说明的决定与依据 |
| --- | --- |
| 权限 | 调用方身份来自哪里、哪个组件执行规则、资源范围、拒绝影响及允许披露的信息；隐藏控件或客户端自报角色不能证明可信授权 |
| 重试与重复 | 操作能否安全重复、如何识别同次尝试、相同键携带不同输入时如何处理、如何查明不确定结果；不能假定非幂等操作可直接重试 |
| 并发修改 | 读写之间什么可能变化、现有版本条件或其他协调机制、冲突行为、保留的工作以及重试/复核路径；会丢弃用户意图的最后写入策略属于产品选择 |
| 多步或外部影响 | 提交边界、部分结果、补偿或核对、可观察进度，以及无法自动恢复时的操作员路径；本地回滚不能撤销已发出的外部动作 |
| 数据与兼容 | 新旧表示、字段缺失与 null/默认值的区别、有效转换、真实需要共存的调用方版本；仅在本次确有需要时设计迁移或兼容回退 |
| 恢复与保留 | 能从哪份证据或版本恢复什么、谁有权执行、哪些永久丢失；不能仅因有备份或撤销按钮就承诺可恢复 |

不适用的行可以省略，已有政策能够决定的直接复用。重要选择仍未知时，说明具体后果并请求
该决定；不要随意填入超时、保留期限、安全等级、兼容窗口或成功率目标。

## 连接到验证

检查修正建议时，同时选择一个合同必须允许的请求和一个必须拒绝的请求。涉及身份、唯一性
和重试时，先说清实际编号范围，例如身份、接口、资源和操作键，再核对同一范围内的请求
内容是否相同。两个独立编号范围内的相同文字不自动构成冲突；明确的全局唯一规则也不能
擅自改成按用户隔离。合法请求与已规定的拒绝条件必须一起保留。更强限制若有价值，应作为
交给其负责人的合同变更建议，不能冒充实现必须修复的错误；已有合同已决定时不制造新选择。

每项重要承诺都选择能区别正确行为与可疑错误行为的观察。例如拒绝后资源不变、相同重试
只产生一次效果、过期写入保留他人的修改、部分外部动作被如实报告而非声称已经全部回滚。
预期来自需求和真实接口，不照抄实现计算。

进程内替身可以验证调用方如何响应冲突，不能证明真实服务执行了原子的版本检查。保留实际
需要的集成或运行证据，不能把 mock、原型、Schema 校验或单元测试通过当作安全/并发认证。
仅在测试边界需要额外设计时读取[实施与测试实践](implementation-practices.zh-CN.md)。

请求审阅时，将真实合同与实现对照。测试即使列出多条需求身份，也可能只验证其中一项。
指出具体未覆盖条件或相互矛盾的效果，允许合理的不同设计，不因缺少偏好的模式就制造发现。
已接受产品行为的变化回到负责人，局部实现缺陷在当前授权工作内修复。
