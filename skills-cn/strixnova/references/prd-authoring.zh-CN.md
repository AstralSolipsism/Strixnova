# 形成、解释、审阅和更新产品需求

需要实质 PRD 或产品级需求编写及阅读版时读取。共同来源、保全、复核和更新规则见
[artifact-documentation.md](artifact-documentation.zh-CN.md)。只在关键产品前提不明确时使用
产品发现，不能因请求文档而重启发现。明确单项变化可以保持普通方向路径。

## 判断请求需要的工作

调查现有产品和领域权威、相关架构或 ADR、输入笔记及旧阅读版，区分：

- 形成需求：展开不完整认识，准备对应的现有候选。PRD 可在确认之前解释候选，但来源与状态
  必须真实。
- 整理现有内容：从适用的精确来源撰写或更新 PRD，不改含义。
- 审阅：对照来源和用途评价现有 PRD，报告发现；没有同时授权编辑就保持文件不变。

根据请求和事实判断写作操作，只有区别会改变授权工作时才询问；
不要让负责人选工作流或提供可查事实。

## 只展开产品仍然需要的决定

从现有认识出发，识别产品实际问题以及文档需要支持的下一项决定：是否继续、纳入什么、能否
进入架构或工程规划。小型内部工具与涉及多角色、外部合同、昂贵失败的产品需要不同深度，
工作量、页数和模板外观不能决定充分性。

只有会改变决定时才使用对应视角：

- 人、问题、结果：连接具体情境、当前替代、代价或未达结果与期望变化。复用产品发现结论，
  只有新证据或负责人纠正会产生影响时才重新打开。
- 旅程与能力：重交互产品需要一个具体使用过程——谁在何种状态开始，关键动作或交接是什么，
  何时产生价值，结束后是什么状态。API、库或单操作员产品可能更适合能力加可观察结果。
  从真实输入或明确提出的例子形成，不编造人物经历或把想象当成用户研究。
- 行为与完成：说明角色或系统能力、触发条件、结果及每项重要要求至少一个可观察后果。检查
  会改变范围或验收的替代、拒绝、空状态、失败与恢复路径；区分必需行为和技术实现。
- 质量与约束：把适用的可靠性、隐私、安全、可访问性、性能、成本、运行或集成问题转成会
  改变决定的边界。阈值来自证据或负责人决定，不知道就保留未知，不能编造数字。
- 范围与取舍：说明首个交付的完整价值、排除项、依赖及不纳入或延后工作的后果，讲清放弃了
  什么。不能为让草稿就绪而把困难要求悄悄移到下一期。
- 成功与不确定性：区分可演示验收与需要真实使用和测量的效果。记录假设、反方证据、未决
  决定和重开条件。优化一项结果可能损害另一项重要结果时才增加平衡指标，不为填模板加指标。

每个必要问题前先调查。一次讨论最可能改变产品或下游设计的一个未决选择，并给出有理由的
建议与后果。纠正后重算受影响认识。一轮形成最多保留五个高影响未知，但不能因问题额度用尽
就声称复杂产品就绪；解决一批决定后可能出现下一轮实际需要处理的问题。

## 含义进入现有权威

产品目的、参与者、问题、结果、能力、排除、产品约束及成功标准属于 ProjectProductDefinition。
领域术语、角色、规则、状态和业务场景属于 ProjectDomainModel。跨单元持久选择属于
ProjectArchitectureDescription 或 ADR。具体变化的范围和验收属于 DirectionDecision，技术
执行属于 EngineeringAssessment 与 EngineeringPlan。使用实际输入合同，不从写作指引推断字段。

阅读草稿发现缺失决定时回到对应权威。授权允许形成候选文件时先准备真实来源候选，再绑定
阅读表达。仅允许讨论时，保留来源明确的讨论草稿及问题，不创造正式身份或采用状态。确认
PRD 段落不能替代对应的既有权威决定。

## 组织 PRD 与覆盖

正文围绕一致的产品目的和行为组织。可按目的与受众、关键流程或能力组、具体要求、适用质量
边界、范围取舍、成功和未决问题展开，顺序与深度按需调整。统一使用领域术语，技术细节留在
其实际来源中，影响产品时明确引用。

绑定精确产品修订及实际使用的领域、架构和 ADR。选定产品定义中的用户、问题、结果、能力、
非目标、约束、成功标准、交付阶段和未决决定逐项得到处置。刻意缩小的阅读范围必须说明，
并处置未纳入项，不能静默声称完整。引用相关领域和架构时不宣称机器已经识别所有语义相关
事实。保留稳定来源身份，不创造第二套独立 FR 身份编号。

## 判断 PRD 是否服务下一项决定

完整复核正文与理解它所需的引用细节：

- 负责人能否作真实范围与取舍决定，选项及后果是否清楚？
- 能力与优先级是否服务所述问题和结果？
- 下游能否判断各重要要求如何满足，包括适用的失败行为和质量边界？
- 排除项、未经确认的假设和阻断问题是否明确？
- 所有重要输入是否保留或得到明确处置？
- 产品、领域、架构及现有方向的角色、术语、边界和承诺是否一致？
- 详细程度是否适合本产品和下一位使用者？

发现必须可处理、有影响和来源，不能只统计章节。证据和现有授权足以解决的直接解决；会改变
产品含义的决定交回负责人。不阻断的未知保留并说明重开条件。正式候选复用既有跨产物复核，
只审阅不授权改写。

负责人能够决定、下游不用发明关键产品决定即可规划时结束，否则明确不能继续的原因。发现
也可结束为搁置或否定。要求且来源允许时交付实际阅读产物；描述“准备怎样写 PRD”不算交付。
后续修改遵循共同更新规则。
