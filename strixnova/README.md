# Strixnova

Strixnova是帮助非专业项目负责人做好软件工程全链路治理的本地工具。能够加载当前安装包随附唯一 Strixnova Skill（技能）、执行命令并理解结构化输出的受支持智能编码代理，是直接调用产品的执行主体。

当前软件版本为 `0.1.0.dev0`（开发候选）。技术检查、安装成功、宿主加载、Agent 工程效果和正式发布分别说明；现有技术记录不代表完整候选验收或效果证明。

项目负责人负责说明预期效果、作出重大取舍并接受实际结果；智能编码代理负责调查、形成有依据的语义候选、实施并解释真实证据；程序只处理结构、版本、状态、确定性规则、本地版本生命周期和真实回执。Strixnova不会启动、调用、调度或管理智能编码代理，不执行远程发布。

模糊的产品或功能想法可以先由智能编码代理按真实缺口界定问题、扩展选项、压测假设、调查证据或归纳产品认识；这些动作按需选择，不是固定阶段。明确请求直接进入现有建设路径，证据不支持的想法也可以被搁置或否定，不会被强制变成 WorkItem（建设事项）或代码。

首次安装使用对应版本离线包中的 README、install.ps1 或 install.py。机器已有 Windows x64、Python 3.12 和 Git 后，安装入口在独立目录中准备 Strixnova 与锁定依赖，返回精确命令和 Skill 路径；不提供 Windows、Python 或 Git 安装程序，不修改系统 Python。以下命令中的 `strixnova` 代表安装返回的实际入口，核对后用 `--help` 查看公开命令。

创建第一个事项时，程序保留并识别正常安装留下的维护文件；安装未收口、记录损坏或夹有无法识别的原有材料时仍会阻断，不要求用户删除维护目录来开始使用。

每项当前验收、约束和已识别风险都须有核验安排，支持命令验证、Agent 审阅、既有证据或明确未核验。必要安排和记录缺失时阻断相应推进；已经明确记录的失败或未核验内容可以保留限制，按适用规则进入结果确认，不会被记成通过。

可观察行为变化在方向验收中保存具体例子，方案逐例关联测试，实际结果区分原生用例执行和 Agent 断言审阅。首批报告器适配 pytest / pytest-xdist，不引入 Gherkin 或额外确认；测试环境须已有对应框架。每条命令一份原始报告，绑定当前方案、例子及声明受测文件的实际字节；输入变化要求重测，历史失败仍保留。详细操作见随包 Skill 的 `behavior-examples` 参考资料。

`strixnova status --follow-ups` 独立查询已接受的延期承诺；后续事项精确关联原问题，只有后续结果被接受才更新派生处置，完成或取消事项不自动关闭原承诺。`strixnova alignment` 按已确认的实施安排处理实现对齐草稿。具体字段与边界由同版 Skill 说明。

`strixnova history` 独立查询进行中、完成及取消事项的已记录事实和证据，包括原生测试报告。`strixnova upgrade` 维护当前格式下的程序、配套 Skill 与数据组合；初始 Authority、活动库和证据格式各为 v1。维护不会转换不支持的格式，未收口执行和新的业务事实会阻止不安全切换或恢复。详见同版 Skill 的 `history-and-upgrade` 参考资料。

一个项目可以包含多个独立 Git 仓库。共同目标保留一份方向、工程方案和整体结果接受，必要内容与验证按仓库限定；接受后依次提交、合入和收尾，保留部分失败、取消与再次规划的历史。服务依赖记录实际版本、契约与环境，缺少后端源码时不会据服务连通性声称源码覆盖。详细输入以同版 Skill 和 CurrentAction 为准。

完整项目文档、开发约束和验收记录位于源码仓库的 `docs` 目录。
