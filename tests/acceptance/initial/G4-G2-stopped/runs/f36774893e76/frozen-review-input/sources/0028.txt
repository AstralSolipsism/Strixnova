12: ## 2. 背景、问题与拆单决策
13: 
14: ### 2.1 业务背景
15: 既有项目仅提供纯函数预约时间区间顺序与时长计算（`duration(start, end)`），无法支撑端到端的预约生命周期管理。本次扩展旨在增加成员自主撤回与运营汇总导出能力。
16: 
17: ### 2.2 核心业务事实与语义纠正
18: 1. **申请严格界定为“待审核”申请**：成员仅能撤回自己发起且状态处于“待审核 (`pending`)”的预约申请；已批准生效的预约不可直接由成员撤回，本轮不开放已批准预约的取消处理。
19: 2. **周报下载为纯传输操作**：周报汇总导出是一次状态统计与文件传输动作，不与预约申请业务实体混同，二者属于不同职责单元。
20: 3. **两项结果拆单独立交付**：
21:    - 成员撤回申请（成果一）与周报汇总下载（成果二）具有独立业务价值与验收标准；
22:    - 拆分为两个关联的 WorkItem：先行推进成果一，成果二作为独立待办事项保持等待，解耦交付风险。
23: 
24: ## 3. 跨单元共用领域前提与一致性约束
25: 
26: 两个业务单元必须在实施前共用核心领域模型与权威规范，严禁各自定义方言：
27: - **申请身份与模型**：共用统一的预约申请实体标识与时间区间属性；
28: - **状态机与决定权**：共用状态枚举（`待审核`、`已撤回`、`已批准`）以及基于可信会话身份的决定权判定；
29: - **并发与审计规范**：撤回与审批并发时基于版本控制只允许一个分支成功；审计记录统一记录操作者、操作身份、原状态与新状态；
30: - **交互边界**：界面交互严格限定为本地终端交互，不增加 Web 端或网络远程服务。
31: 
32: ## 4. 详细业务需求规格
33: 
34: ### 4.1 成员待审核申请撤回 (对应 WI-20260928-9A2A1BC1)
35: - **主体与权限**：操作者身份必须来自可信宿主会话，严禁信任传入的请求体角色或所有者字段；仅能操作本人申请。
36: - **状态流转**：仅当申请处于“待审核 (`pending`)”状态时允许撤回，撤回后状态更新为“已撤回 (`withdrawn`)”。
37: - **幂等性与响应丢失**：对已撤回记录再次撤回，返回相同撤回成功响应，且**不重复记录审计日志**；若客户端丢失响应，可重新查询实际状态。
38: - **并发保护**：成员撤回与运营审批并发发生时，采用版本号并发控制，仅允许先到达者成功，后到达者明确失败。
39: 
40: ### 4.2 负责人自然周汇总导出 (对应 WI-20260928-DB4C76AE)
41: - **主体与权限**：仅允许可信宿主会话认证为运营负责人的用户触发下载。
42: - **统计范围**：按本地指定的自然周（如 `YYYY-Www`）统计该周内预约申请的当前状态分布。
43: - **隐私保护与最小化**：周报导出数据仅包含宏观统计指标，**严禁包含成员的私人联系方式（电话、邮箱等）**。
44: 
45: ## 5. 明确非目标 (Non-Goals)
46: 1. 本轮不实现已批准生效预约的取消、改期或重新审批流程；
47: 2. 不实现周报的自动定时邮件/短信外发，不实现缴费或资金清算功能；
48: 3. 不增加 Web UI、HTTP 远程 API 或分布式网络服务。
