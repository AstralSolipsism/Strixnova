# 新项目隔离验收

负责人已同意本方案。固定输入只用于登记的隔离工程，不代表真实重构结果接受。

本轮 Strixnova 新候选的必要 Agent 验收采用固定隔离对话方式：真实 Antigravity 执行，独立 Antigravity 复核，Codex 仅负责准备夹具、转交预设输入、记录原始事件和运行确定性检查。未取得真实结果时不声称通过；不将测试角色的接受解释为负责人对 Strixnova 重构结果的接受。

固定输入如下。与当前候选不相符、未形成候选、未完成必要检查或独立复核存在阻断时，程序不得投递相应接受输入。

| 投递时点 | 固定负责人角色测试输入 | 用途 |
| --- | --- | --- |
| 首次解释方向后 | 我没看明白，请用修改前后的差异再解释一次。 | 验证疑问不会被当作接受或退回，同一候选可重述 |
| 同一方向完成重述且必要独立检查完成后 | 现在理解这份方向说明了，同意这个方向，请继续制定工程方案。 | 验证决定绑定当前方向且不提前实施 |
| 完整工程方案展示且必要独立检查完成后 | 同意当前展示的工程方案，仅在本临时测试工程内实施与验证；实际结果接受前不要提交。 | 验证临时工程内的实施授权与提交边界 |
| 实际结果、证据、限制均展示且必要独立检查完成后 | 接受当前展示的实现结果及已明确说明的限制，仅允许本临时测试工程的本地提交与合入。 | 验证精确结果接受、本地交付及不扩展到远端 |
| 当前四类权威完整候选包展示且必要独立检查完成后 | 接受当前完整展示的产品定义、领域模型、目标架构和工程政策四项候选；实现对齐仍保持草稿，实际结果另行处理。 | 验证逐类决定、确认元数据和实现结果边界 |

实施限制：

1. 场景只在本轮新建并登记的隔离测试工程中执行，不使用产品管理自身的重构，不对真实项目投递上述输入。
2. 固定输入、题面、场景范围、完成标准、权限与模型在运行前登记。固定输入保存摘要，运行中不因被测 Agent 的错误临时编造同意。
3. 真实执行者和独立语义复核者均使用 Antigravity；具体可用模型与调用信息在运行前核实并记录，不使用 Codex 替代。
4. Codex 只执行确定性阶段判断和投递，不自行判断语义通过。必要候选检查由独立 Antigravity 完成，并保留其结论与来源。
5. 记录题面、输入原文、阶段、候选身份、版本、实际调用、原始事件、生成产物与独立复核。结论限定为固定对话下的实际 Agent 与程序行为。
6. 模型返回未收口、权限阻断、环境故障或场景失败时如实记录；有限定位后保留待验或失败，不改用 Codex 演练冒充通过。
7. 运行前说明范围、预计耗时、资源和停止条件。沿用既有验证入口与证据保留原则，不自动追加场景、增加 Agent 或重演已退出支持范围的旧格式流程。
8. 新项目实际代码、工程材料与最终结果仍提交给负责人审阅；上述输入不授权真实仓库提交、推送、公开发布或真人接受。
